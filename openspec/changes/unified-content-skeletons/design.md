## Context

Flutter 项目已安装 skeletonizer 2.1.3。旧版资料和评论已有骨架；新版首页、Mio 影视栏目、搜索、日历和部分详情仍使用进度线或转圈。追番通过本地收藏仓库同步读取，我的和设置直接展示本地状态，没有需要模拟的首屏网络等待。

## Goals / Non-Goals

目标：视频卡片先显示稳定轮廓，栏目各自结束加载；网络封面等待时保留真实标题；刷新不清空已显示的数据；分页在尾部占位；错误和空状态及时退出骨架。

不修改接口、分页算法、SDK、规则解析、播放器生命周期。播放器解析、下载和同步进度不是内容占位，继续保留。不给本地页面增加延迟。

## Decisions

1. 共用 `lib/bean/widget/content_skeleton.dart`，提供主题化 Skeletonizer.zone 和纯 Bone 布局。复用依赖，避免每页各写动画。低对比主题色在 1400 ms 周期内柔和脉冲，减少动画时 duration 为零。
2. 海报卡片采用现有 1:1.42 比例，圆角 12，标题和辅助信息各一条。横向栏目按实际宽度计算；网格允许传入原页面的 gridDelegate。推荐卡片复用真实高度，横向信息卡片保持日历封面与正文排列。讨论使用评论轮廓，剧集使用按钮轮廓。
3. 以“loading 且目标数据为空”判断首次骨架。已有内容时保留原布局，分页只追加有限一行或两行骨架。各栏目独立判断，不等待所有请求。
4. CachedNetworkImage 的 placeholder 改为骨架，errorWidget 和空 src 保留静态占位，防止失败后永远闪动。图片加载期间不隐藏标题，不编造评分或剧集数。
5. 骨架不触发网络请求、播放、筛选或分页，不生成假业务对象；IgnorePointer、ExcludeSemantics 与一条“正在加载内容”提示隔离交互。
6. 新版搜索与详情导入共用组件；已有 InfoCommentsView 和 EpisodeCommentsView 骨架保留，匹配分集期间补充评论轮廓。关系、角色、人员资料按实际布局占位。

## Risks / Trade-offs

- 网络封面中途失败 → 立即回到静态缺图状态。
- 文本缩放或窄屏布局溢出 → 共用组件使用约束和 textScaler，覆盖 320 dp 与双倍文字测试。
- 网格占位与真实卡片高度不同 → 原 gridDelegate 复用，推荐占位明确高度。
- 多处动画消耗 → 限制初始占位数量，Sliver 按需构建，系统减少动画时停止。

## Migration Plan

只改展示层；改动前文件备份在 `.dart_tool/content-skeleton-before-20261012/`，相对路径保持原目录。新文件可以独立移除。所有既有用户修改保留，回滚只恢复本次备份，不恢复到 Git HEAD。

## Scope

允许：共用骨架与封面组件，新版 home/calendar/miomedia/player 的内容等待分支、search 页面导入和结果加载分支、对应测试、本变更规范。禁止：SDK、规则、接口、存储、路由、设置、播放器控制器及无关格式化。共享旧版封面加载随本次统一，旧版已有骨架不替换。
