## Context

现有页面只有空状态，桥接不支持 modules。提供的 SDK 新版 transport 支持 ECSM，旧内置文件不支持。数据服务与页面均已有取消、独立加载、竖版卡片和来源详情入口。

## Goals / Non-Goals

Goals: 按原始序号展示前十和服务端 name；同 categoryId 去重缓存，不同 ID 完全隔离；与其他首页数据并发、独立显示；错误可重试；没有分类映射或栏目时显示真实空状态。

Non-Goals: 统计七天热度、按累计量排序、推断窗口、合并榜单、改播放逻辑、重置设备、探测未核验端点、用 Bangumi 作品 ID 打开来源作品。

## Decisions

- `hotRank` 是受限 SDK 操作，固定 `/video/modules`。三个字段必须提供，正整数从 1 起算。Python 只投影 MOD_818368 与原 items 前十，以减少 Web/Android 的传输和 JSON 工作量。没有栏目返回 list=[]。格式错误报告 PARSE_ERROR，不能伪装成空榜。
- MioRanking 记录 categoryId、栏目原始 name/k/cover/layout/boardTabs 与带位次的 MioVideo；window 和 metric 显式 null。位次只取原数组索引+1；不排序、不去重、不题材筛选。
- 首页推荐/热门共享类别 0 的缓存。分类 ID 来自现有元数据；已核验动漫子分类可使用 SDK 示例中的名称/ID 绑定，实际资料优先。动漫“全部”若缺少来源聚合分类则保持空状态，不将全站榜冒充动漫榜。
- 分类榜独立于目录/分页；首次出现按需请求，切回复用已加载缓存，刷新只重取当前榜。刷新失败保留旧榜并标注失败，可重试。取消和过期响应不能覆盖当前分类。
- 沿用深色紫色竖版卡片，在评分位置显示位次；标题和作品名原样保留。加载采用已有骨架屏，错误与无榜单区分。Web/Android 共用代码。
- 用户追加的选集优化共用 TextPainter 测量：短名至多八字且能放入小格，中名能放入半行则两列，其余全宽两行。间距与播放标记预留固定空间，选中不改变尺寸。按卡片档位组织行，档位变化时换行，保持来源顺序；短名弹层仍用 GridView，混合档位用惰性 ListView；页面内最多 12 个选集。
- 运行中确认旧 suite 的首页完整响应解密接近 20 秒，叠加网络会触发默认请求预算；提供的 SDK 加速版刚更新，因此原样同步 suite。48 组新旧加解密一致，真实响应解密中位数从 19,646.957ms 降到 286.993ms。没有扩大客户端请求预算。

## Risks / Trade-offs

- 450KB 上游响应仍需完整解密 → 复用新版 SDK，Python 投影前十；榜单不阻塞目录和其他卡片。
- 来源文档的分类汇总与现有应用元数据可能不一致 → 实际元数据优先，缺少 ID 不复用 0。
- 原运行服务尚未加载新文件 → 独立端口验证新服务，部署保留同一设备文件；不重复尝试曾被审批拒绝的进程终止。

## Migration Plan

原样同步 SDK transport 与导出，记录哈希；增加只读操作、Dart 模型和 UI；测试并构建；用加载新代码的服务验收。回滚只恢复本次备份代码并重建，不触碰身份文件。
