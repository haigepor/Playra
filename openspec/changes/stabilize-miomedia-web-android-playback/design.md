## Context

现有页面已经复用单个 media_kit 播放器，但每次换线重取剧集，静态选中标记不能反映播放状态。实测 10 个作品/线路组合的直链和首片传输通过，7 种线路中仅 4 种在浏览器诊断窗口内解码成功。Web 非空请求头会触发 Media UnsupportedError。

## Goals / Non-Goals

**Goals:** Web 与 Android 共用缓存、有限恢复、真实播放状态。手动点击的线路先尝试，失败后最多两次换线；新选择取消旧任务，页面释放取消全部待办。

**Non-Goals:** 不修订协议和 SDK 算法，不重置身份、不执行账户操作、不承诺修复全部上游媒体。Aliplayer 本次只核验，不在缺少正式配置时替换工作中的原生播放器。

## Decisions

- 页面会话专用协调器：剧集缓存按该作品和线路隔离、5 分钟有效、合并在途请求。取消单次 UI 选择只放弃结果展示，不取消其他选择共享的剧集读取；释放会话才取消底层读取。
- 自动换线只匹配唯一的完整名称，或双方明确表达同一集数的普通集名；不按数组位置、不按跨线路 episodeNum 直接猜测。目标请求使用该线路自己的真实 episodeNum。
- 实测成绩仅按平台/线路记录近期成功起播耗时与失败惩罚；未实测时保留服务端顺序。显式选择永远先尝试，自动恢复上限三个实际播放请求。
- 播放器仍由页面持有；每次新媒体先停止旧媒体并重新绑定当前尝试的错误监听。起播窗口最多 25 秒，以视频尺寸与播放进度共同确认工作，HTTP ready 或 open 返回均不直接认定成功。
- 标记使用固定 14 dp 三柱 Flutter 动画，播放器播放、非缓冲且已有进度时运动；暂停冻结、减少动画/后台静止。仅标记局部重绘，不因动画重建页面或 SVG。
- Aliplayer 可用 URL 模式和 HLS，但域名/License 与转码能力需独立核验；当前 media_kit+同源网关避免新增商业依赖和双播放器生命周期。

## Risks / Trade-offs

- [进度与视频尺寸不是逐帧解码质量指标] → 浏览器核验额外检查 totalVideoFrames；Android 真机解码单独验收。
- [错误流不携带媒体代次] → 停止旧媒体后重新订阅，并在当前尝试内收集错误；新播放取消旧尝试，迟到结果不回写。
- [标签不一致导致保守匹配失败] → 提供手动线路选择，不猜测特辑/预告对应关系。
- [用户暂停或浏览器要求点击播放] → 不能把用户暂停当作源失败；起播检测遇到暂停且媒体已就绪时保留播放器供手动继续。
- [上游单次延迟] → 有限重试、即时取消、真实错误提示；不盲目提高后台并发或复用一次性凭证。

## Migration Plan

无数据迁移。新增组件局限于 MioDetailPage。回滚页面使用 `.dart_tool/interface-playback-audit-20261012/miomedia_detail_page.before.dart`，新增协调器、标记和测试独立移除。保留此前用户改动。
