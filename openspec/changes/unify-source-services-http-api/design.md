## Context

现有 RuleEngine 已支持搜索/剧集各自使用 XPath 或 JSON API。其默认请求器和日志依赖 Flutter，独立 Dart HTTP 服务不能直接运行。首页目录另有 DM84/7sefun 专用采集，新旧播放使用平台 WebView；Web 已有 Node 代理和浏览器解析服务。

## Goals / Non-Goals

Goals: 六项用户要求全部纳入同一变更：统一身份/能力/模型、搜索/剧集、目录适配、解析/验证码/会话、分页/分类/健康、可运行 HTTP API。

Non-Goals: 不调整页面视觉，不自动修改用户规则安装列表，不把网页站点伪装成原生 JSON API，不宣称所有来源支持目录/分页或可以播放。不公开部署、不改变全局 Codex 工具配置。

## Decisions

1. 使用纯 Dart 来源服务和 DTO，复用现有 RuleEngine。将引擎的 Flutter 默认请求/日志移动至条件运行时适配，独立服务注入请求器，避免另写 Node XPath/JSONPath 引擎。
2. 来源 ID 优先使用持久化 sourceId；旧规则使用大小写归一的名称派生兼容 ID。规则更新沿用已有 ID，规则版本、协议级别、HTTP API 版本分别保存。sourceConfig 是可选扩展，旧字段与非活动 API 配置继续保留。
3. 内容引用保留 providerId 和 rawRef（可为 URL 或 ID）。HTTP 内容 ID 为不透明引用，不能让调用方提交任意上游 URL。线路/剧集具有独立对象，提供旧 Road 转换。
4. 服务层维护按操作健康记录与有限并发聚合搜索，取消及空结果不计为来源故障。标准分页区分上游分页与已获取集合的本地分页；未知总量/下一页不伪造。
5. 将现有首页采集原样移入目录适配器注册层，HomeRuleCatalog 保留兼容返回结构与只读内置兜底。分类保留类型、地区、形式、原始栏目及证据，无法判定时为 unknown。
6. RequestContext 携带取消、会话标识与超时。解析/验证码桥接已有原生实现及 Node 浏览器后端；会话隔离 Cookie/UA，超时清理，取消不允许过期结果回写。
7. HTTP 服务监听 127.0.0.1 独立端口，通过版本化 /api/v1 路由暴露来源、分类、目录、搜索、内容引用、线路、解析任务与验证码任务。Web Node 提供同源转发，独立 API 通过本机请求可调用。响应只含规范 DTO，规则鉴权头和原始解析页面不出现在公共响应。
8. 默认注册内置规则，允许通过启动参数加载独立规则 JSON/列表，不写用户安装目录；远程规则由显式配置/目录加载接入同一注册器。

## Risks / Trade-offs

- 来源站点改版或需要验证码 → 操作健康与明确错误，不用搜索成功冒充播放成功。
- 无上游目录或分页 → 返回能力说明与 UNSUPPORTED；集合切片明确为 local 分页。
- 验证需要浏览器上下文 → 保留平台桥接，HTTP 后端依赖现有 Node/Chromium，不强行移除该依赖。
- Flutter 条件运行时漂移 → 同时运行纯 Dart HTTP 集成测试、既有规则测试和 Flutter 构建。
- 新旧持久化兼容 → 仅添加可选字段，导入导出与混合模式回归测试必须通过。

## Migration Plan

按来源契约、应用接入、目录接入、解析会话、HTTP 服务、整体验证依次推进。新增模块先经契约测试，再接入既有调用方。保留 Plugin/首页兼容入口，回滚可移除入口委托并停用新增 HTTP 服务，不删除用户数据。

## Open Questions

无阻止实施的问题。第三方站点可用性、原生设备实测分别作为环境验证，不等同于接口实现完成。
