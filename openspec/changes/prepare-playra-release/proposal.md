## Why

Playra 仍混有上游应用名称、开发入口和关于页推广链接，正式版用户体验与项目身份不一致。公开仓库中的官方 tags 与自有版本未区分，大量未提交实现和 SDK 敏感配置需要在提交前整理。

## What Changes

- 将用户可见应用名称、平台显示名、安装包元信息、更新来源统一为 Playra，保留已有安装与存储兼容标识。
- 正式构建隐藏日志、组件实验室等开发入口和直接路由；诊断构建通过明确开关启用。
- 重设计关于页，突出品牌、版本、使用说明、隐私与许可信息，移除源代码及上游社区推广入口。
- 自有发布仅使用 `playra/v*`；官方 tag 映射为 `upstream/<原版本>`，迁移保留原提交并在确认后调整旧远端引用。
- 按功能整理既有修改并提交推送 main；排除构建产物、设备身份、敏感 SDK 配置与已有子模块删除现场。
- 保留电影播放失败检查，完善安全阶段错误，真机恢复必须有设备证据。

## Capabilities

### New Capabilities
- `release-branding`: 品牌一致性、正式版入口策略与关于页体验。
- `release-repository-policy`: 自有/官方版本隔离、公开提交安全与构建依赖说明。

### Modified Capabilities
无。

## Impact

Flutter 页面、平台应用元数据、更新服务、GitHub Actions、SDK 本地构建输入、仓库文档、回归测试和 Git 引用。没有改变 SDK 密码算法或重置设备身份，不删除应用数据，也不重写 main 历史。
