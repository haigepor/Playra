## Context

复用 RuleEngine、SourceService、SourcePlaybackService 与唯一 PlayerController。现有 16 条规则都有 anime 声明，但 SourceSheet 未过滤类型或有效剧集。远程更新不能覆盖独立本地设置。

## Goals / Non-Goals

Goals：动漫/影视隔离、可用来源展示、基于实测记录的自动优选、有限同集回退、手动优先、HTTP resolve 配置接入。
Non-Goals：不新增影视站点、不执行任意远程脚本、不并行创建播放器、不按相同列表位置跨源恢复、不声称未测速来源最快。

## Decisions

- 来源领域声明放在 sourceConfig.domains，接入方式由 resolveApi 配置推导并在 manifest 输出；旧 type 显式迁移，缺失 type 视为 unknown。本地启停与分类覆盖、统计存入单独 source-policy.json，避免远程更新丢失。
- 作品标题/别名规范化仅移除空白与标点，保留季号、年份与 SP/OVA；自动候选需唯一标题匹配和唯一正片集号映射。人工确认仍保留。剧集目录缓存 5 分钟，按作品、来源版本与详情地址区分。
- 并发检索最多 4；解析保持串行，按近期播放/解析耗时与失败惩罚排序，冷启动采用规则配置顺序。单轮最多 3 个来源/线路候选，各最多一次临时错误重试，原生总预算 120 秒、Web 180 秒。取消与无资源不计来源故障。
- 自动选择通过弹层明确入口开启；人工选定来源保持固定，可手动重试/换源。恢复当前进度只针对可靠同集身份，未知映射要求重新选集。
- 统一初始化错误和播放器媒体错误事件，自动模式触发受限恢复；用户切集/来源/退出作废旧流程。暂停和后台不触发首帧等待超时。
- 外部算法服务通过 sourceConfig.resolveApi 请求配置与 JSONPath 结果映射接入；请求使用现有 RuleEngine executor，HTTP 服务沿用安全网关。直链与网页解析在共享解析边界区分。

## Risks / Trade-offs

严格匹配可能遗漏带站点后缀的标题 → 保留别名/自定义检索与人工候选入口。不同来源剪辑时长可能不同 → 不确定映射不自动续播。串行解析无法证明全球最快 → 基于近期样本优选并记录实际结果。原生首帧与平台网络差异 → 设备验收另行记录。

## Migration Plan

不重写用户规则；运行时从显式 type 生成领域，新增本地策略文件。旧 JSON 和已有路由参数继续可用；回滚应用代码后旧客户端忽略新配置，本地策略文件可保留。
