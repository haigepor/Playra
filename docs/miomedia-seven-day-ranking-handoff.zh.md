## 研究步骤

### 1. 梳理配置和实际调用路径

先读取 `profile.py/config.py`、SDK 客户端、文档和已有内容联调脚本，确认当前环境、协议前缀和调用路径。复用现有身份持久化与握手校验，不输出密钥或设备标识。

对 404 分别核验：请求前缀、接口版本、HTTP 方法、环境配置、服务是否部署该模块，以及文档是否对应另一套服务。根据提供方文档／官方请求样例核验，禁止批量猜测路径或参数。

### 2. 区分栏目配置与榜单内容

核验 `home/modules` 返回的是栏目定义、直接作品列表，还是需要二次查询的配置。若有 `id/k/layout` 等字段，解释它们的真实含义，追踪实际内容请求所需的栏目 ID、分类 ID 和分页字段。

如果首页不同栏目的数据来自多个请求，记录依赖关系和请求顺序，不能为了展示一栏而等待所有分类数据。若发现统一首页响应，也要标明各块能否独立加载或缓存。

### 3. 核验“七天”的统计语义

必须回答：

- 时间窗是最近连续 7×24 小时、含当天的 7 个自然日、上一个完整自然周，还是服务固定周榜？
- 是否返回窗口起止时间、时区、榜单生成时间或更新时间？若缺少字段，如何由提供方文档证明语义？
- 排名基于有效播放次数、播放人数、观看时长、综合热度还是其他指标？单位和尺度是什么？
- 排序是由服务端直接提供，还是客户端需要根据明确指标排序？并列、缺失指标与榜单位置如何处理？
- 是否支持电影、电视剧、综艺、漫剧、动漫分别查询？分类 ID 从哪里取得？是否需要登录态？

参数名称不能凭空假设为 `days=7`、`sort=hot`、`period=week`。未验证的参数一律标为 TODO。

### 4. 分类、分页与边界验证

对实际支持的分类分别验证第一页与下一页：

- 真实请求明文、HTTP 状态、解密成功、业务码与返回字段。
- 页面是否变化、是否重复第一页、是否跨分类混入内容。
- 服务端 `rank` 是全榜排名还是页内序号；客户端展示顺序不能伪装成服务端热度名次。
- 榜单是否有固定 Top N、分页上限、快照 ID；分页时榜单刷新会不会引发重复或漏项。
- 空榜、分类不支持、接口缺失、网络错误、业务拒绝需要区分，不能全部表示为“没有数据”。

读取热榜不需要播放换取、广告奖励、账户写操作或重置设备身份。保持同一身份，限制为必要的只读请求。

## 交付内容

1. **研究报告**：列出端点、用途、支持范围和证据，分类为 VERIFIED／DOCUMENTED_ONLY／UNAVAILABLE；分别记录 HTTP 状态和业务码。
2. **参数契约**：字段类型、必填性、默认值、允许值、分类映射、分页与时间窗；未知项明确 TODO。
3. **脱敏样例**：保留作品 ID、分类、名次、指标、窗口字段与必要展示数据；删除密钥、凭证、身份标识与包含鉴权参数的地址。
4. **标准库最小示例**：复用 SDK `Client.request` 与持久身份，演示一次真实榜单查询及一页翻页；不能重新实现密码学算法，不能引入 requests、numpy、Lua 运行时等依赖。
5. **适配建议**：在确认契约后给出 Playra Python 桥接的只读操作名与映射建议；未核验前不修改现有白名单。

## 验收标准

- 至少一个实际支持分类返回真实作品，解密与业务状态都成功，能够证明近七天窗口；或提供明确的接口缺失／不支持证据。
- 已验证分类参数和分页边界，ID 保持字符串，展示分类与服务分类一致。
- 不将评分、累计播放量、推荐列表或热搜关键词替代榜单。
- 不使用假数据填榜，不制造榜单统计，不清空设备身份。
- SDK 原有自检继续 ALL PASS，密码学实现不变，日志和报告无密钥或凭证。
- 若当前平台没有此能力，最终交付应是“暂无法接入”的证据、待平台确认的问题和所需接口契约；Playra 继续保留清晰空状态。
