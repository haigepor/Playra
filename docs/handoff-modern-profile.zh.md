## 2. 改造前的审美与功能诊断

### 2.1 已核实的页面结构

入口 `/tab/my/` → `lib/pages/my/my_module.dart` → `InterfacePageHost` → `ModernProfilePage`。

新版 `lib/presentation/modern/pages/profile_page.dart` 目前使用 `ModernPageScaffold`：标题「我的空间」，一个「让追番更合心意」预览说明区，随后依次展示组件实验室、观看历史、离线缓存、播放规则、数据同步、全部设置。

| 优先级 | 证据与问题 | 对使用的影响 | 设计决定 |
| --- | --- | --- | --- |
| 高 | 预览说明与切换按钮占据首屏主区域 | 进入页面先看到开发状态，难以找到自己的内容 | 首屏改为观看足迹，预览说明移至页面版本行 |
| 高 | 组件实验室排在历史/下载之前 | 开发工具与日常功能权重不匹配 | 实验室保留在末尾「应用」分组 |

| 中 | 每个入口单独一张卡片 | 边框重复，滚动长，视觉层级近乎相同 | 高频功能用三列快捷入口，其余按用途合为分组列表 |

### 2.2 页面定位与唯一视觉特征

定位为“随时回来的个人观看空间”。按用户进入后的任务排序：查看足迹 → 找历史/下载/规则 → 调整观看体验 → 管理数据 → 查应用信息。

选定的视觉特征是**一本轻量观看手记**：开放书页与书签线稿表达积累感，真实统计作为内容。保持与番剧封面页面一致的深色底与细边框。不给每个模块加插画，不加入等级、会员卡、打卡日历或没有数据支撑的图表。

账号身份只在「数据与同步」分组中表达。首屏不依赖登录，也不设置巨大头像和登录横幅；即使离线且没有账号，页面仍然完整。

### 3.1 标题栏

- 标题统一为「我的」，22px/700，左边距 20px；工具栏最小高度 48px，不重复添加系统状态栏高度。
- 右侧单个设置齿轮，20px 图标、48×48px 点击范围，tooltip/读屏名称「全部设置」，跳转 `/settings/`。
- 标题栏固定，内容只有一个主滚动区域。避免将整页放进固定高度 Column 后再嵌套多处滚动。

### 3.2 观看足迹卡

- 全宽、16px 圆角、16px 内边距，表面沿用 `surfaceContainerLow`，边框 1px。
- 标题「观看足迹」14px/600，下方一句 12px 弱化文案。正文颜色使用主题变量。
- 两项统计横排，28px/700 数字，12px 标签。显示 `watchedBangumiCount` 和 `watchedEpisodeCount`；下载数放入下载快捷入口，避免重复三指标仪表盘。
- 默认高度约 148px，使用内容自然撑高和最小约束，不能固定高度截断大字体。
- 统计卡本身不点击；去历史的动作集中到下方「历史记录」。不用没有动作含义的箭头。
- 有记录文案「每一段故事，都有迹可循」。零记录使用「你的观看足迹，从这里开始」及「观看后，记录会保存在这里」，保留 0 值，不用破折号冒充加载。
- 全空时在卡片增加「去发现番剧」文字按钮；通过现有 TabShell 的切换方式到发现，检查底部选中态同步，不能叠加第二个根导航页面。
- 数量 0–9999 原样显示；更长数字在卡片内缩小数字或换行，读屏保留完整数值。不要用单纯省略号替代数字。

### 3.3 高频快捷入口

- 顺序固定：历史记录、离线缓存、播放规则。三列等宽、列间距 8px、每项最小高 88px、图标 22px。
- 整项可点击，轻底色或透明背景即可；不用三个大阴影卡片。图标有相同大小的 36px 淡色承载区。
- 历史副文案：有记录「回到上次观看」，零记录「暂无观看记录」。点击始终进入历史列表，不自动续播任意内容。
- 下载副文案：0 时「管理离线内容」，有值时「N 集任务」。这包含全部状态，禁止标成「N 集已缓存」。
- 规则副文案「管理播放来源」，不展示未经确认的规则数量或可用性。
- 320px 与大字体同时出现时，三项改为纵向紧凑行，每行 ≥64px；保证文案完整，不把文字压到图标下方多行溢出。

### 3.4 分组设置列表

- 三组标题「观看偏好」「数据与同步」「应用」，12px/600，组间距 24px，标题至容器 8px。
- 一组一个 16px 圆角容器；行间分隔线从文字起点开始，避免重复整圈边框。

## 5. 数据状态、文案与行为

### 5.1 统计只复用一个来源

使用 `MyController.watchStats`，不在 build 中重复遍历仓库。

`WatchStats.from` 已按番剧 ID 和 `(番剧 ID, 集数)` 去重，仅有 progresses 的历史参与；数量不是完播判定，也不是观看时长。`downloadTaskCount` 是所有状态的集任务总数。数据清空后允许即时回到 0。

MyController 初始化为全 0，attach 会同步刷新；当前没有独立的统计 loading/error 字段。首版不凭 0 推断“仍在加载”，也不加永远转动的骨架。若仓库真的抛错，必须沿现有异常策略保留明确失败，而不是 catch 后悄悄显示 0；新增错误模型须单独说明必要性。

### 5.2 Bangumi 行状态（按下表顺序判断）

| 条件 | 主状态/说明 | 点击行为 |
| --- | --- | --- |
| `isConnecting` | 正在验证连接 | 打开 Bangumi 设置，禁止页面自动重复发起验证 |
| Token 为空 | 未连接；连接后可同步追番 | `/settings/bangumi/` |
| 当前有 `lastError` | 连接异常；点击检查 | 同上，不把原始 Token/请求异常长串塞到列表 |
| 有 Token 且 `initialized == false` | 待验证；打开设置检查连接 | 同上，不能说已登录 |
| 已验证且同步关闭 | 已连接 · 同步关闭；用户名可显示第二行 | 同上 |
| 已验证且同步开启 | 已连接 · 追番同步已开启 | 同上，不能标记“已全部同步” |

用户名不作为全应用身份，不据此自动创建头像、昵称缓存或新的账号系统。root build 只读状态，网络验证只由现有显式操作触发。

## 7. Flutter 结构与生命周期方案

### 7.1 最小模块分工（下一阶段创建）

```text
lib/pages/my/my_module.dart                 注入既有 MyController
lib/presentation/modern/pages/profile_page.dart
                                           状态监听、路由与挂载边界
lib/presentation/modern/profile/modern_profile_view.dart
                                           纯展示，接收 WatchStats/同步展示状态/回调
lib/presentation/modern/profile/widgets/    仅复杂且可独立验证的卡片/分组组件
lib/presentation/modern/modern_shell.dart   新版四根页底部颜色统一
```

优先在 view 内保留小私有组件；不要一行设置拆一个文件。若同步状态推导开始影响可读性，可加一个只读 presentation model，不创建新的服务或存储。所有统计沿用原 MyController，避免生成无必要的 MobX 文件。

### 7.2 挂载与返回

1. `my_module.dart` 将 `inject<MyController>()` 传给新版页面；测试和调用处同步改构造函数。
2. 新版页面变成有生命周期的容器。照旧版 MyPage 用 `_attached` 保证 attach/detach 成对，结合 RouteVisibility，覆盖页面后释放根页统计订阅，返回恢复。
3. 不 dispose 注入的共享 MyController；仅解除当前页面自己的监听。dispose 前判断是否已 attach，防止 `_viewerCount` 下溢。
4. 控制器实例更换时先 detach 旧实例再 attach 新实例；新旧界面切换时共享仓库数据保持一致。
5. view 使用 Observer 读取 watchStats；Bangumi 使用已有 ChangeNotifier。监听注册不放 build，销毁时移除。
6. 设置返回或 App 恢复时重新读取 WebDAV 配置；不要调用整个应用初始化。返回刷新要用 mounted 保护。
7. ModernHomeScope 限制在新版 root 页面内。ModernShell 内部一次计算统一深色 theme 并复用背景/边框，避免三处条件遗漏；旧版 Shell 与设置详情页沿用现有主题策略。
