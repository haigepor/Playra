## 4. 当前页面风格基准

以项目实际 Theme 和组件为来源，页面通过 `Theme.of(context)` 取色，不直接到处硬编码色值。

| 项目 | 当前参照与使用方式 |
| --- | --- |
| 页面背景 | `#11141c`，低亮度深色，保持连续背景 |
| 内容面 | `#1b202c`，用于输入框或必要分组，不要把每段文字都包成卡片 |
| 弱状态面 | `#202638`，用于轻提示或选中背景 |
| 主文字 | `#edf0f8` |
| 次级文字 | `#a5afc5`，注意正文仍可读，不以极低透明度隐藏重要提示 |
| 主色 | `#a7b7ff`，用于选中、主要操作和少量强调 |
| 边界 | `#30384a`，弱分割优先，减少整圈高对比边框 |
| 字号层级 | 页标题约 22；内容标题 16 或 20；正文 14；辅助说明 12。使用当前 textTheme，避免整页大标题堆叠 |
| 图标 | 优先既有 Lucide 线性图标，主要控件 18–20，次级信息 14–16；视觉尺寸与触摸区域分开 |
| 触摸区域 | 主要按钮及可操作图标至少 48dp；不能为了紧凑把点击区域缩成图标本身 |
| 圆角 | 控件通常 12，必要内容卡通常 16；避免同页同时出现圆形、大胶囊和多种大圆角 |
| 间距 | 页边距通常 16–20；组内 8–12；组间 16–20。根据实际内容调整，不盲目压缩正文 |
| Tab | 原生 TabBar、文字宽度的 3dp 圆角短线、48dp 行高；有滑动和选中状态，尊重减少动画设置 |
| SVG | 低对比度线稿，仅装饰，不抢正文。装饰不进入读屏语义，不引入脚本、外链或位图 |

页面“紧凑”应表现为减少无意义空白、提高信息层级，而不是小字体、窄点击区或截断长内容。保持系统大字体、SafeArea、键盘缩小和长文本滚动。

## 5. 优先细修：人物资料页

目标文件：`lib/pages/info/character_info_view.dart`、必要时 `character_page.dart`。新版入口从播放一体页的作品资料 → 角色 → 人物进入。

### 已实际观察

- 390 宽页面中人物头像按钮约为 **88×214px**。源码的 `height:132` 只作用在图片，旧版顶部/两侧内边距与底部“查看原图”仍叠加到整个按钮。底部图标加文字在窄列里也显得拥挤。
- 人物姓名与配音被放进资料卡；“基本资料”又接在右侧 `profile` 列中，导致资料受窄列限制，封面左侧下方出现较多空白。
- 人物关系使用胶囊，资料摘要和更多资料又使用卡片分组，首屏装饰层级偏多，与已确认的紧凑影音方向有差距。
- 外部人物资料 GET 实际成功，姓名、配音和基本资料已经显示。封面代理失败不是人物数据不存在；不要用假人物资料替代。

### 建议实施顺序

1. 先对照实际页面确认整张头像按钮的尺寸，而不是只看内部图片的约束。
2. 给现代分支独立的头像呈现：完整控件约 88×132，圆角 12，图片保持人物原图比例。去掉旧内边距与文本底栏；可用角落的小型展开图标提示，整张图片仍可点击。
3. 保留 Hero、原图预览和语义“查看人物原图”。图标可加 Tooltip，装饰图标不重复朗读；图片为空时用简洁占位，不在 88px 窄区域塞长说明。
4. 首行只放头像与身份摘要：人物关系、中文名、不同的原名、配音。姓名最强，关系和原名较弱，配音可读但不抢标题。
5. “基本资料”移到首行下方使用完整宽度：条件允许时两列，窄屏或大字体改一列。保持字段与值的真实对应，避免重复字段。
6. 简介、更多资料、非结构化资料顺着阅读，不机械包成层层卡片。组间可先从 24 收到 16–20，长正文保留合适行高。
7. 所有调整限定现代分支。旧版头像大小、资料布局及默认调用行为保留；不改角色 API、评论分页、原图路径或路由参数。

这组是最高优先级。先完成后回到页面判断比例，再决定是否还有必要调整资料分割线。
