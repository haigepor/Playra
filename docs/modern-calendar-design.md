# 新版放送日历：分析与设计

日期：2026-10-11。状态：设计完成，尚未修改日历页面代码。本次新增本文件与布局示意 SVG，不修改旧版、新版页面、存储结构或运行服务。后续实施属于独立变更。

## 1. 设计结论

日历的主要任务是“查看某个星期有哪些番剧放送，找到自己在看的作品并继续观看”。采用**紧凑的每周排期导航 + 当天竖向列表**，视觉直接沿用发现页；月历只在未来具有准确逐日、逐集事件数据时考虑。

页面的特色是领域化的星期排期导航。封面与内容承担视觉层次，不增加大幅宣传卡、玻璃背景或装饰性统计。当前两块占位说明和“选择页面样式”大按钮全部移出内容区；样式切换仍保留在已有设置入口。

布局示意：[modern-calendar-wireframe.svg](design/modern-calendar-wireframe.svg)。示意中的封面、标题和状态为占位，不代表真实节目、更新进度或可播放状态。

## 3. 数据核验：哪些信息真实存在

已读取实际调用与旧日历逻辑，并请求 `https://next.bgm.tv/p1/calendar`。本次响应的七日数量依次为 11、10、12、11、14、20、25；这些数量是此次接口快照，不是固定产品数据。

当前季度接口返回按 `1…7` 分组的条目，包装字段为 `subject` 和 `watchers`；没有逐集准确时刻或播放源更新时间。官方 [Private API 契约](https://raw.githubusercontent.com/bangumi/dev-docs/master/api.yaml) 的 `CalendarItem` 同样定义这两个字段。旧代码只保留 `subject`，丢弃了 `watchers`。

| 信息 | 当前来源 | 展示规则 |
| --- | --- | --- |
| 标题、封面、评分、地区/媒介标签 | 日历 `subject` | 直接展示，中文名优先；缺图使用占位，缺评分不显示 0 分 |
| 每周放送星期 | 日历响应的外层 `1…7` 分组 | 直接保留，不能让模型的默认星期覆盖它 |
| 放送时刻 | 条目详情 infobox，部分条目存在 | 可选补充；保留出处和时区，不将其称为播放源更新时刻 |
| 热度 | `watchers` 与评分票数不同 | 有包装数据时按在看人数排序；不能把 `votes` 标成在看人数 |
| 在看/想看/看过/搁置/抛弃 | 本地收藏仓库 | 使用项目 `CollectType`，经现有映射处理远端枚举 |
| 上次观看的集数与进度 | 历史仓库 | 仅显示“上次观看”，不是“已更新至”或“今日待看集数” |
| 播放源可用性、可播放剧集 | 已有规则服务、播放流程 | 用户打开详情/点击续播时查询，不对每张卡启动解析 |
| 准确的某集已更新、停播、延期、下一集倒计时 | 目前没有完整统一数据 | 第一版不推算、不承诺，后续需要可信事件来源 |

### 必须处理的现有边界

1. **首播日期与每周放送星期混用。** `BangumiItem.fromJson` 按 `date/airtime.date` 推算星期，缺日期时用 `2000-11-11`，结果落到周六。当前季度列表的外层分组是可信来源；历史搜索仅凭首播日期不能确认固定放送星期，无法确认的条目进入“排期待定”，不能硬塞七日。
2. **历史季度数据不完整。** 非镜像分支固定获取 4 页 × 20 条；搜索限定日本和有排名的动画，可能遗漏国漫、无排名作品和第 81 条以后内容。新页不能把这种结果包装为“完整季度放送”。后续改为按实际分页结束条件加载，并以明确能力支持地区筛选；镜像与公开 API 回退均需保留来源、是否截断和失败状态。
3. **空列表与失败混用。** 当前接口会捕获错误并返回空集合，控制器把空季度当超时。共用服务应区分合法空结果、解析失败、网络错误与部分成功，不能要求用户对一个空季度无限重试。
4. **季度切换竞争。** `loadSeason` 在加载期间直接忽略新请求。新控制器需采用请求版本号或取消令牌，只接纳最后一次选择的结果；保留上一次成功快照，不先清空整页。
5. **时刻与时区。** 首页 `HomeAiring.withDetail` 目前提取单一 `HH:mm`，遇到多个时刻或 24+ 小时表达则待定，尚无完整时区/跨日规范。日历不直接把该字符串当北京时间；来源明确后才能换算，并同时调整星期。暂不对不明时区的时刻进行混合排序或倒计时。
6. **观看完成状态。** 历史进度在临近结尾时归零，零值也可能表示刚开始，不能据此推断单集已看完。明确“看过”来自收藏状态；第一版提供可靠的上次观看与续播。

当前使用的 `/p1` 是新网站私有接口，官方说明其无兼容性保证且不支持跨域，见 [官方开发文档](https://github.com/bangumi/dev-docs/blob/master/README.md)。因此网络适配必须留在服务层，Web 使用已有同源代理，页面不直接请求该域名。

### 主题与密度

- 复用发现页语义色：背景 `#11141c`、卡片 `#1b202c`、正文 `#edf0f8`、次要文字 `#a5afc5`、强调 `#a7b7ff`、边线 `#30384a`。这些值来自现有主题，组件应读取主题 token。
- 内容左右边距沿用 20；卡片间距 10–12；圆角 12–14；边框弱化，不加厚重投影。
- 标题建议 20–22 / 600；星期 13–14，选中略加粗或直接变大；番剧标题 15–16 / 600，辅助文字 11–12。沿用现有中文字体，不引入新字体依赖。
- 手机顶栏约 48–52，星期栏约 52–60，筛选行约 36–40。首屏尽早出现番剧；不复刻当前两块大型介绍卡。
- 番剧卡片基准高度约 124，封面约 74 × 104；实际随两行标题和字体缩放扩展，不硬编码造成裁切。
- 评分贴封面左上圆角；时间放封面右下，无独立背景、无文字阴影；封面底部用轻微黑色渐变过渡到透明，继承首页要求。
- 无可信时刻时显示“时间待定”，不在页面追加整段来源说明提示；具体来源可在条目详情或筛选说明中查看。
- PC 悬浮时只轻微放大封面（建议 1.035），由封面圆角裁切；不增加整卡悬浮背景。键盘焦点另用清晰边框表示。

### 响应式与安全区

- 主体最大宽度先沿用发现页 760，手机单列；宽屏可在该范围内用两列同型卡片，不做七列周视图作为第一版。
- 星期栏始终可访问：固定顶栏 + 内容滚动，与发现页现有结构一致；进入列表不会把星期导航滚出屏幕。
- 320 宽屏或大字体时，星期项至少保留 44 的点击区域，必要时横向滚动并自动露出选中项；不压缩触摸区域。
- 页面只消费顶部安全区，底部系统间距由 `ModernShell` 负责；列表底部保留常规内容间距，不重复叠加导航高度或系统 inset。
- Android 状态栏颜色/图标与暗色作用域一致，刘海、打孔与手势导航需实机验收。透明状态栏不意味着允许文字贴近系统顶部。

## 5. 交互与状态

**星期切换：** 默认当前星期。点击切换与左右滑动列表联动；下划线随位置连续平移，约 220–280ms 缓出。文字样式直接切换，不做字号动画。快速连续点击也以最后一次选择为准。每个星期独立保留滚动位置；点击已选星期可回到列表顶部。

**今天与季度：** “回到今天”只在选择了其他星期或历史季度时出现，点击同时回到当前季度和当前星期。顶部季度入口采用现有年/季度语义，移动端底部弹层、宽屏 Popover；未来季度若无来源能力则不可选。历史季度只展示星期，不伪造某年某月某日的精确集数更新记录，也不提供没有事件数据支撑的上一周/下一周翻页。

**筛选：** 默认“全部”，快捷项“仅追番”映射旧版“只显示在看”。日漫/国漫、隐藏看过、隐藏抛弃、排序放入紧凑筛选弹层；地区无法识别的内容保留在全部中。第一版日历聚焦动画排期，不直接复制发现页电影/电视剧/综艺等缺少日历来源的分类。星期计数若展示，应计算筛选后实际条目数，筛选变化与卡片同步。

**列表分配：** 全部模式下分为“我的追番”和“其他放送”，同一作品只显示一次；仅追番模式取消空的“其他放送”栏目。没有追番时直接展示当天全部列表，不保留空追番卡片。主体不做触底无限加载；季度数据分页是服务内部取数，不等于页面无限滚动。

**排序：** 默认先在看后其他，同组内仅对已规范到同一明确时区的可信时刻升序；时间待定项置后。时间相同或未知时依次使用实际在看人数、评分票数、ID 作为稳定次序。详情补充时间应批量提交更新，避免滚动中卡片持续跳位；也可保持当前快照直到下次刷新。用户选“热度/评分”时采用该主排序，避免界面标称和实际排序冲突。

**操作：** 点击主体沿用 `/info/`；“继续”走 `HistoryPlaybackService`，保留历史来源和线路；没有记录时只给详情入口。收藏状态优先只读展示，若增加快捷追番，必须走现有 `CollectController` 同步流程，不能直接写 Hive 绕过远端同步和变更记录。

**状态完整性：** 初次加载用与卡片等高的骨架；刷新保留内容；网络失败有重试；有缓存时保留旧列表并标记非打断式状态；合法空日、筛选无结果、未加入任何追番分别显示对应轻量空态。局部详情失败只使该条时间待定，不使整个日历失败。应用恢复前台、跨过午夜以及收藏/历史变更时更新今天和本地状态，已手动选择的星期不自动跳走。

## 6. 业务结构与文件边界

建议保持与发现页相同的三层结构，网络和元数据规范化独立于新旧 UI：

```text
Bangumi API / 镜像 / 可选公开接口回退
             ↓
CalendarService → SeasonScheduleSnapshot
             ↓
ModernCalendarController ← 收藏仓库 / 历史仓库
             ↓
ModernCalendarView + 星期导航 + 番剧卡片
             ↑
ModernCalendarPage（路由适配、依赖注入、详情/续播回调）
```

旧 `TimelineController` 可逐步改为调用同一个 `CalendarService`，保留对旧视图的公开属性与方法；新版不依赖旧版私有 Widget。不要把 HTTP API 或播放源目录塞进视图：先前统一的 `SourceService` 负责搜索、目录、剧集与解析，Bangumi 日历是元数据排期能力，应通过独立服务组合。以后若需要日历 HTTP API，应新增明确契约复用此服务，而不是假设已有 `/api/v1` 自动包含日历。

建议新增/调整边界，均为后续实施计划：

| 文件/目录 | 职责 |
| --- | --- |
| `lib/services/calendar/calendar_models.dart` | 季度、日程条目、星期/时刻证据、数据源、部分成功/缓存/截断状态 |
| `lib/services/calendar/calendar_service.dart` | 共用取数、错误转换、分页、去重、详情补充与缓存 |
| `lib/presentation/modern/calendar/modern_calendar_controller.dart` | 选中星期、筛选、取消/版本、收藏历史关联、稳定排序 |
| `lib/presentation/modern/calendar/modern_calendar_view.dart` | 纯布局与交互回调 |
| `lib/presentation/modern/calendar/widgets/` | 星期栏、季度入口、番剧卡片、筛选与空态；不要过早拆成大量单行文件 |
| `lib/presentation/modern/pages/calendar_page.dart` | 改为薄路由适配层 |
| `lib/presentation/modern/home/home_theme.dart` | 复用并逐步提炼共享现代主题，保留原入口兼容 |
| `lib/presentation/modern/modern_shell.dart` | 日历底栏统一暗色，安全区只消费一次 |
| `lib/pages/timeline/timeline_controller.dart` | 经共用服务获取规范化日历，旧接口和视图保持兼容 |

模型用 `(season, subjectId, weekday)` 标识排期：同一天同 ID 去重，但可信的每周多日放送不能跨星期直接去掉。星期不明保留独立待定集合；不要新增 Hive 字段来保存页面计算结果。`CollectType` 的本地数值与 Bangumi 远端数值不同，复用已有 mapper。

请求策略建议：季度快照按来源/季度缓存，先读上次成功结果再刷新；详情只补可见条目及少量预取，最多 3–4 并发并按 ID 去重。缓存 TTL 建议季度列表 30 分钟、详情 24 小时，属于待实施参数，不是当前已上线配置；手动刷新应明确失效对应缓存。切季/离页取消旧请求；地区识别使用结构化标签，不按标题猜国别；历史与收藏通过现有 `changes` 实时合并。

组件采用当前 Flutter `shadcn_ui` 与 Material 组合，沿用已有 Lucide 图标、按钮、底部弹层和 Popover 习惯。仓库已有 `ShadCalendar` 展示页，可复用未来的日期选择控件；它不是每周放送导航，第一版不把月历强塞到主视图，也无需安装另一套 UI 库。
