# MioMedia 播放页样式优化与七天榜交接

日期：2026-10-12；项目 `C:/Users/haige/Desktop/Playra`。

## 图片问题与原因

| 优先级 | 证据／问题 | 影响与修改 |
|---|---|---|
| 高 | 用户截图选集弹层为浅色，错误条浅底浅字 | `MioDetailPage` 的 State 上下文位于 `ModernHomeScope` 外，弹层和部分显式颜色读到了旧主题。使用深色 Scope 下的 Builder 上下文构建页面与打开弹层，明确弹层背景与文字颜色 |
| 高 | 剧集边框有旧主题绿色，错误提示难以辨认 | 剧集按钮在页面与弹层中共用同一组件，深色填充、10 dp 圆角、淡紫色当前集标记；错误条采用深色卡片、图标、清晰正文与原剧集重试入口 |
| 中 | 单集电影打开选集后几乎整屏空白 | 弹层高度按当前分段的行数计算，上限 80% 视口；单集为紧凑弹层，长剧集保持网格滚动 |
| 中 | 页面标题、辅助资料、线路与选集层级不一致 | 标题 20 dp，辅助信息 12 dp，分组标题 15 dp，来源线路使用真实名称与条数，选集标题和线路／总集数分两行 |
| 中 | 弹层关闭入口与大字体体验不足 | 选集和简介增加标准 IconButton 关闭入口；图标明确使用灰色，定位使用淡紫色；大字体自动减少网格列数 |

现有 Flutter Material／shadcn_ui 主题是本项目组件体系，未安装 React shadcn 或引入第二套样式系统。修改范围仅为 MioMedia 播放一体页及其测试、交接文档。

## 保留的业务边界

- 顶部 16:9 播放区域与页面播放器生命周期保持现有实现。简介与选集操作不创建新播放器。
- 分段和升降序只改变显示，点击与重试始终使用真实字符串作品 ID、线路 code、剧集编号；不根据显示位置推断编号。
- 当前播放集标记与定位保留。媒体失败后可在播放器区域重试，底部信息区保留明确错误提示。
- 已选中的线路重复点击不再清空已加载剧集；剧集加载失败仍保留原有独立重试入口。
- 不将来源作品当作 Bangumi 作品，不新增虚假评论、评分、收藏或播放统计。
- 没有修改 Python SDK、规则、设备身份、密码学实现或热榜数据。

## 七天榜交付

完整复制提示词位于 `docs/miomedia-seven-day-ranking-handoff.zh.md`。它要求其他项目核验 `home/modules` 的栏目定义与内容请求，复查默认环境的历史 404，证明实际七天窗口、指标、分类和分页。文档中的示例栏目 ID 不硬编码，累计播放量、评分和推荐列表不替代近七天统计；不能证明能力时继续使用空状态。
