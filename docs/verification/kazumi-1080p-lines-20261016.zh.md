# Kazumi 解析故障与真实 1080p 线路筛选（第二轮）

日期：2026-10-16，Windows / Chromium / Node v25.2.1。沿用原 16 条固定官方规则，没有更改其站点、XPath 或默认线路顺序。

后续变更：2026-10-17 已按用户要求接入 akianime → mutefun → giriGiriLove 自动主备顺序，其余规则保留手动入口；见[后续验收记录](kazumi-auto-priority-20261017.zh.md)。以下实播结论保留本轮当时的验收口径。

## 验收口径

使用生产 RuleEngine / SourceService、真实站点、生产 Node 解析与媒体代理，以及 Playwright MCP 操作 Playra Web 页面。搜索样本为《吞噬星空》《葬送的芙莉莲》；清晰度读取实际 `videoWidth/videoHeight`，同时核对约 26 分钟的正片时长、播放时间推进和帧数。站点标题、接口 200、播放器“高清”标签、3 秒占位片均不算成功。

本轮“稳定通过”只表示所列作品的两集均完成原站与 Playra 重复起播、每集持续播放至少 30 秒。页面实播通过手动选择所列官方线路进行，不代表已经把站点名单写死到自动排序。它不是整站所有作品或未来可用性的保证；其他作品仍走实际尺寸门槛。起播有失败、需要重试或超时的来源单独列为波动，不授予稳定结论。

## 已确认的问题与修复

1. **全局 Referer 导致子请求 403，外层表现为解析 502。** 原解析器通过 `extraHTTPHeaders` 把规则根地址应用到每个 iframe/XHR。baimao `/playinfo` 的对照请求：实际播放页 Referer 为 200，旧根地址 Referer 为 403。现在入口 Referer 只用于主文档首跳，子资源使用 Chromium 自然生成的页面上下文。baimao 默认线已从 502 变为解析成功、HLS HTTP 200。
2. **播放器 HTML 被误识别成媒体。** 原正则扫描整条 URL；`player.html?url=https://.../index.m3u8` 会被抢先当作 HLS。现在依据 URL pathname 或实际媒体 MIME 嗅探。回归使用真实 Chromium 嵌套 iframe，确认返回真正的媒体请求。
3. **实际媒体请求头在 Dart 层丢失。** 解析结果现在携带实际 Referer、User-Agent、Origin；经过 `VideoParserEvent → WebViewVideoSourceService → VideoSource → PlaybackInitParams` 到原播放器，同时来源 HTTP API 的不透明媒体句柄保留同样上下文。只允许公开请求头，忽略任意 Cookie/Authorization 注入。原生平台没有这些头时继续使用默认空映射。
4. **AGE 静态 CDN 的端口及受信任证书根。** 除已有播放器主机外，仅增加实测的 `xcdn.khfed.com:8443` HTTPS 例外，继续校验公网地址、凭据、协议和精确主机。随后确认 Node 默认 CA 报 `unable to get local issuer certificate`；开启系统 CA 的对照启动使脚本与解析恢复。正式网关现在合并 Node 默认根与系统受信任根，保留证书和主机名校验；未设置 `rejectUnauthorized=false`。旧 Node 缺少 `tls.getCACertificates` 时保留默认信任行为，本轮实际验证版本为 v25.2.1。
5. **3 秒 Full HD 占位视频不能算正片。** AGE 样本出现 1920×1080、总长 3.088 秒的 MP4。Kazumi 自动确认新增对已知总长不足 10 秒片段的拒绝，仍保留手动入口。已用真实播放器启动状态回归证明旧实现会误接受、修复后拒绝；这不是通用广告识别或全程 ABR 清晰度锁定。
