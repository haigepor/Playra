# 电影播放失败与播放器统一

基线：`dac19b50`。用户要求：深度分析电影解析/播放失败，使用模拟器验证，并与动漫使用相同的安卓播放器。复杂度 L：涉及 SDK 错误契约、电影换线和共享播放组件。沿用 Flutter Material/shadcn_ui 与现有 PlayerItem，不新建第二套控制界面。

原有未跟踪分析文档和 `fastlane/.libmpv-android-video-build` 变化保留。范围：MioDetailPage、MioPlaybackCoordinator、SourceMediaPlayer、VideoPageController 的来源展示上下文、PlayerItem/PlayerItemPanel 的来源能力边界、miomedia_adapter 的安全错误码，以及对应测试和本记录。不修改私有 SDK 算法、不重置设备身份、不伪造 Bangumi 身份。

## 已取得证据

- `emulator-5554` 安装最新 Release，电影《唐探1900》高速线路 TC 正常播放，实际进度 `00:00:32 / 02:15:20`。
- 《毒液：最后一舞》高速线路正片复现“暂时无法取得播放资源”。同一数据有稳定线路 1080P、备用线路1 HD中字。
- 原流程已共用 PlayerPlaybackController 原生解码核心，但 MioDetailPage 使用默认 Video 控件，动漫使用 PlayerItem/PlayerItemPanel，自定义手势、全屏、倍速等界面不一致。
- 针对性 Android 脱敏日志：SDK `ffm3u8` 在 1.083 秒返回 ready，媒体启动返回 false（总 26.469 秒），随后出现 `tcp: ffurl_read returned 0xffffff92`。首个线路没有在 25 秒内正常起播，与资料/目录加载成功不是同一验收结果。
- 桌面固定测试身份的 SDK 对照：高速和备用线路返回 ready，HLS 清单 HTTP 200；稳定线路在 8.4 秒返回 unavailable，SDK 原因前缀为“JSON解析失败”。这只能证明桌面接口路径，不代替 Android 的媒体验证。
- 原换线逻辑仅按集名精确/数字匹配，正片、1080P、HD中字互不匹配，所以失败后跳过备用线路；所有失败统一显示 unavailable，信息丢失。

## 修复约束与验收

1. 只有真实元数据确认的电影，原线路和目标线路均唯一一条目录时，允许按同一作品身份换线；连续剧、特辑、多条目录保留严格匹配与真实 episodeNum。
2. 保留解析失败、超时、媒体失败、身份冲突等稳定原因；不输出媒体令牌、原始上游正文或 SDK 凭证。
3. 影视原生复用动漫的 PlayerItem/PlayerItemPanel；共享解码配置、播放手势、进度、倍速、比例、全屏与 PiP。电影的目录和真实作品 ID 保留独立来源上下文，隐藏不适用的 Bangumi 收藏、弹幕绑定和一起看。
4. 测试先证明备用线路被跳过，再验证修正。模拟器重测电影失败样本、正常电影、全屏/返回/暂停，并检查动漫不回归。

回退：仅还原本轮文件至基线或 revert 本轮提交，不 reset 工作区与设备数据。

范围补充：用户进一步要求修复重复返回按钮、首页空状态居中并扩大影视接口测试。MioDetailPage 的封面返回按钮只在尚未挂载原生播放器时显示；MioCategorySliver 的空状态改为占满剩余内容视口居中，新增 `test/miomedia_category_test.dart` 几何回归。允许修改 `miomedia_category_view.dart` 与该测试。

- 修改文件静态分析无错误/警告，保留 5 项既有样式提示。Web 与 Android Release 均需从最终代码构建后交付。

测试覆盖电影与多集目录边界、真实集数、三次尝试上限、取消与资源释放、身份冲突、广告校验停止、HLS 格式提示、Referer、错误码脱敏、原动漫控制上下文和空布局。未对所有影片、全部集数或长时间网络波动作无限保证。
