## 源码对应的执行逻辑

1. `lib/services/source/miomedia/miomedia_service.dart:119` 从 `player[]` 读取 `playerCode/playerName`，校验代码格式，没有 1 条或 7 条的数量限制，也没有固定代码白名单。
2. `lib/presentation/modern/miomedia/miomedia_detail_page.dart:93` 在详情成功后用完整 `result.lines` 选取初始线路；页面对 `video.lines` 全部生成选线控件，数量显示为 `video.lines.length`。没有人为把多条线路裁成一条。
3. SDK 的 `playback.py:309` 明确说明 `code` 来自详情中的 `player[].playerCode`。调用顺序为详情 → 线路剧集 → 清晰度/换取 → 必要的客户端解析 → 播放器。
4. `lib/services/source/miomedia/miomedia_playback_coordinator.dart:153` **一次自动起播最多实际尝试 3 条候选线路**，按顺序尝试。它是回退预算，不是 SDK 只有三条线路，也不限制页面手动选线。
5. 优先当前指定线路，其他线路按本平台记录的起播成功/耗时排序；切线会作废旧请求，跨线路切集要求集名/编号匹配，不按列表位置盲跳。

- 当前是 **1 个 SDK 提供方**，它下面有多种线路；16 条旧动漫规则属于另一种接入方式，不能和这 7 种线路直接相加当接口总数。
