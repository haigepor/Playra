# Playra 全页面样式与交互细节审查

日期：2026-10-14。源码基线：`74a0441a5c8b500a4160c0ddeb843725cb68470a`。

本次为 L 级跨页面审查：研究实际入口 → 建立规范建议 → 运行验证 → 整理问题与复核。本次只生成分析文件，不修改应用代码、主题偏好、规则或收藏数据；未保存的规则模板已退出。

## 1. 结论与优先级

现有深色背景、淡紫主色、细边框、短线 Tab 指示器，可以继续保留。当前问题主要是共享规范没有覆盖所有局部页面，以及部分页面没有按播放器容器尺寸做响应式处理。

优先处理以下三项，价值高于单纯调整圆角、装饰线和阴影：

1. **P1：Web 播放器在手机宽度下裁掉全屏等操作。** 390px 实际播放时，右侧工具栏伸到约 491px，网页全屏、全屏按钮位于容器之外。
2. **P1：动漫详情未播放时，横屏隐藏详情与选集入口。** 宽度大于高度就进入满窗口布局；未播放封面没有打开侧栏的按钮，用户必须旋回竖屏才能访问这些内容。
3. **P1：影视频道首屏出现错误的动漫空状态。** 顶部写“暂时没有可展示的番剧”，下方已有电影列表。误导用户判断资源是否可用，并占据首屏。

其次是轮播命中区域、无名称播放按钮、主题设置与强制深色的矛盾、空状态/表单/标题栏规格分散。没有发现需要全面推翻视觉风格的证据。

## 6. 建议统一的token与组件规则

此表是**建议规范**，不是本轮已落地的代码。尽量由现有Flutter主题与组件承接，不引入第二个UI框架，不把shadcn_ui Flutter项目迁移成React。

| 类型 | 建议值/规则 | 应用边界 |
|---|---|---|
| 颜色 | background `#11141C`、surface `#1B202C`、selected `#202638`、text `#EDF0F8`、muted `#A5AFC5`、primary `#A7B7FF`、border `#30384A` | 保留当前暗色；亮色另用已有light色板，别手写切换 |
| 语义色 | error/success/warning独立，不用品牌色表示所有状态 | 提示和实际错误分层；装饰线允许低对比，不等同按钮边界 |
| 文字 | page22/700、section18/600、body14/1.5、metadata12、action13~14 | 10px仅可选角标；正文与核心按钮遵从系统放大 |
| 间距 | 4/8/12/16/20/24/32；内容边距小屏16、普通手机20、宽屏24~32 | 同类型页一致；播放器内容可16，不跟设置子树字号漂移 |
| 圆角 | field12、普通卡16、专题卡20、sheet20、角标6~8 | 不一刀切；每一种用途固定映射，不到处手写12/14/16/20/24/28 |
| 操作区域 | 项目触屏目标48dp，文字Tab48高；视觉Icon18~22 | 视觉小图标可保持小；命中区独立，Web窄版工具栏需功能收纳 |
| 标题栏 | 普通二级页56高、22px标题、单一返回入口 | 平台是否居中由明确政策决定；SysAppBar目前iOS强制居中，主搜索AppBar则左对齐 |
| 筛选层级 | 一级Tab短线；二级筛选轻背景；排序/地区清楚标注 | 四分类与来源分类不混淆；超过宽度横滚并留渐隐/部分下一项提示 |
| 宽度 | 阅读/表单/搜索760；资料网格可960~1200；播放与详情按容器/状态分栏 | 宽屏主导航仍四格全宽是当前实现，可后续优化但不是阻塞问题 |
| 表单 | label→field→help/error；提交邻近字段；busy+结果反馈 | 搜索/密码/URL/代码分别输入配置；避免悬浮主按钮与长距离空白 |
| 空状态 | 图形、标题、说明、至多一个主要动作 | 全页/栏目/输入前提示三种，位置依据可用内容区而非屏幕固定坐标 |
| 加载 | 初始骨架/局部刷新/尾部分页/解析/首帧缓冲分开 | 已有结果继续展示，搜索进度共滚动；失败不继续显示无限骨架 |
| 动画 | 继承disableAnimations；hover/focus/按压清楚 | 不重复嵌套动画；既有轮播焦点暂停/前后台暂停应保留 |

建议先把稳定色板、字体、间距、圆角、命中区集中到现有modern主题层，再让首页/设置/二级页/播放页只覆盖**用途差异**。不建议为了“统一”合并所有页面的业务状态、接口控制器、搜索逻辑和播放器实现。

### 对比度抽样

按当前源码纯色配对计算：正文/背景16.15:1，辅助字/卡7.40:1，主按钮底/文字8.13:1，边框/卡1.39:1。前三组文字没有必要整体提亮；弱边框不能单独承担必要操作识别或焦点状态。未逐个计算海报叠字、透明叠层、禁用态和所有亮色组合。

参考依据：[W3C普通文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[W3C目标尺寸最小值](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。WCAG 2.2 AA目标尺寸要求24×24 CSS px或满足例外；本文建议的48dp是项目触屏体验目标，不能说成WCAG统一要求48。
