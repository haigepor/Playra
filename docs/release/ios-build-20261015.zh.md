## 发布与打包链路

现有 `.github/workflows/release.yaml` 的 `workflow_dispatch` 接受 `platform=ios`；`plan → quality → cloud(ios)`。quality 必须先完成分析、全量 Flutter 测试及构建助手/输入/网关测试。

iOS job 使用 macOS runner 与指定 Xcode，`tool/cloud_build.py` 执行 `flutter build ios --release --no-codesign`，将设备 `.app` 封装至 `Payload/`，检查 arm64、iPhoneOS、Playra 名称、版本、CRC 和未签名状态，生成 IPA、JSON 收据与 SHA256SUMS。附件保留 14 天。

仓库当前没有导入 Apple 证书与 provisioning profile 的步骤。`PLAYRA_SOURCE_RUNTIME_URL` Secret 也未配置；iOS 未内置 Android Python 桥接，相关来源功能需要单独提供 HTTPS 服务。

## 签名与免费安装

用户希望可直接安装的已签名 IPA，但尚未提供有效签名身份。搜索发现有第三方公用企业证书列表，未核实授权、吊销状态及目标设备可安装性，因此不能将其声明为可靠的签名输入，也没有把第三方私钥写入仓库或 Actions。

免费个人安装可使用自己的 Apple ID，通过 Windows 上的 Sideloadly 或 AltServer 签名安装；免费签名需定期刷新。这一步需要用户在本机授权账号，云端未签名产物不等同已签名可安装产物。
