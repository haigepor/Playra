# 本轮重要设计决策

2026-11-22。用于解释本轮区域稿相对上一轮全页稿的细化，不作为已经实施的代码状态。

| 冲突或问题 | 选择 | 代价及处理 |
| --- | --- | --- |
| 用户要求统一深色，早期已有浅色分区草案 | 全部最终区域板重新生成深色，包括弹层、空态和标注背景。 | 浅色中间结果不列为交付图；旧提示词明确标为废弃，保留生成过程可追溯。 |
| 竞品大主视觉容易挤占首页 | 借鉴主观看操作与层级，推荐图保持 16:9，保留续播和栏目可见性。 | 不逐像素复刻 Netflix 的高主视觉，也不新增其他产品的导航业务。 |
| 七列日期在 320dp 无法兼顾全部可见与 48dp 宽热区 | 当前周内部可横向滚动，选中日期自动完整可见。 | 使用明确的上周/下周操作，避免与原有横向切周手势竞争。 |
| 大字号月历数字网格拥挤 | 优先使用项目已有日期输入模式，保留切回月历。 | 输入模式需要字段验证、明确日期格式与键盘避让，不增加滚轮选择器。 |
| 固定底栏会裁掉大字号标签 | 根据图标、标签实际高度和安全区增长。 | 底部会占更多空间，内容保持可滚动；留白必须引用底栏实际高度。 |
| 统一所有图片比例会损害紧凑列表 | 海报网格与搜索完整封面使用 2:3；日历 48×64、历史 96×54 是明确的缩略图角色。 | 缩略图允许裁剪，不拉伸；同一角色的比例不能随标题变化。 |
| 用户需要快速判断能否继续观看 | 当前观看集、更新集数与总集数分开表达。 | 别名移到作品资料，缺少数据时省略，不伪造更新或观看进度。 |
| 进度条看起来很细，拖动却需要准确 | 保持细视觉轨道，提供至少 48dp 高的可操作区域。 | 需要划分手势优先级，不能与亮度/音量手势互相抢事件。 |
| 一次换集失败不能破坏旧集状态 | 保留旧集的播放与选中，提示目标集失败，重试指向目标。 | 状态表达更复杂，需要分别管理当前、目标、加载与失败，不能用单一 selected 代替全部。 |
| 参考竞品会诱发多余功能 | 只采用当前产品功能可以承接的布局模式。 | 不绘制账号、会员、弹幕、下载、付费和额外收藏分类。 |

颜色的目标组合按相对亮度计算，结果见 [颜色与尺寸计算.json](颜色与尺寸计算.json)。这仅验证所选纯色组合的数学对比，不能证明位图、半透明遮罩、实际字体和运行时界面已经通过无障碍测试。
