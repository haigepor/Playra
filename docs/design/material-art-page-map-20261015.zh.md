## 2. 整体分工：图片、SVG 与留白

| 类型 | 使用材料 | 合适位置 | 不应承担的职责 |
|---|---|---|---|
| 页头 / 单张品牌卡背景 | 透明 PNG，哑光纸张与胶片浅浮雕 | 每页最多一处，主体集中右侧，有明确文字保护区 | 不传递状态，不代替按钮，不画真实数据、文字和数字 |
| 栏目 / 操作图标 | 手写 SVG 或已有统一图标库 | 18–28px；操作命中区仍保留 44–48px | 不使用纸纤维和复杂光影，不强行加入每个图形都一样的星星；前三名徽章按用户最新独立图像任务处理 |
| 空态插画 | 优先现有 SVG | 96–136px，低高度或大字体时可收缩 | 不把无结果、未开始、失败画成同一语义 |
| 卡片局部装饰 | 极简 SVG，圆润纸角 / 胶片边 / 票根缺口 | 只在卡片的保留区域使用，不能覆盖海报与文字 | 不在每张卡重复一张大 PNG，不用伪进度或伪勋章 |
| 视频、表单、设置、正文 | 留白、分组、真实状态与标准图标 | 播放画面、选集、输入区域、密集设置 | 不用装饰解决布局密度、信息层级或可读性问题 |

统一颜色继续沿用 `#11141C` 背景、`#A7B7FF` 主强调、`#C9D3FF` 柔和高光。生成图允许灰蓝、灰紫与靛蓝的材料变化；不要用统一色 ColorFilter 抹掉纹理。小 SVG 继续保持清晰的粗圆轮廓和局部块面。

## 3. 三件已接入背景与后续微调建议

以下保留原构图设计依据；“当前”是已核对的代码，“后续建议”尚未实施。当前日历与追番统一使用 48px 高度保护控制区，不能把此前建议的 64–80px 当成已落地参数。

### P1：日历——没有印字的放送日程卡

**语义与构图**：两张略微错位的圆角日程纸页、一枚小型纸夹、局部胶片页边。前页可以有抽象的浅浮雕分栏压痕，但不画星期、日期、时间、数量和对勾。它表达“排期”，不制造假的日历数据。材质与发现页同源，去掉花枝与月夜风景，不能仅把发现图换一个图标。

- 已落地文件：`modern-calendar-header-art.png`，2172×724 RGBA。原设计要求主体集中右侧、保留左侧与底部透明保护区；实际裁切需以产品页验收为准。
- 宿主：`calendar/modern_calendar_view.dart` 的 `ModernPageArt(kind: calendar)`。当前顶部是标题与季度按钮，下方是星期条和筛选条，不能让页边轮廓包住季度按钮。
- 当前手机规则：宽度为内容宽 .82、上限 360，高度裁切 48、opacity .22；渐隐停点为 `[0, .38, 1]`。后续只在季度按钮周围仍有 8–12px 清晰留白时微调，不直接恢复原建议的 64–76 高度。
- 320px：最多露出一张主纸页和一个后层页角；如果控制区拥挤，将 opacity 降到 .14–.18，而不是压缩星期触控尺寸。
- 当前宽屏：已传 `contentMaxWidth: 760`，装饰锚定内容栏右缘，宽度最多 360。需运行检查这一定位在 1440 宽下的效果，不再重复列为待接入工作。
- 排版优先：今日/选中日期/放送时间先清楚；时间信息和列表分组比纸夹细节重要。

### P1：追番——带书签的个人片单夹

**语义与构图**：半开的薄纸收藏夹，露出两张抽象海报纸片，一条短布纹书签从其中一页垂下。没有人物、封面版权图、收藏数量、星级或“已完成”标记。薄层叠放比厚重立体书本更适合小页头。

- 已落地文件：`modern-library-header-art.png`，2172×724 RGBA。原构图要求主体靠右、左侧留白，书签在底部保护区前结束；页面仍需按当前 48px 裁切检查轮廓。
- 宿主：`library/modern_library_view.dart` 的页头。标题、搜索、更多操作、状态标签都保持现有位置；不向卡片网格铺背景。
- 当前手机规则：内容宽 .82、上限 360，裁切高度 48、opacity .22。后续微调优先让最清楚的纸张边缘避开搜索/更多操作，不通过增高页头保留所有细节。
- 320px：可以只保留收藏夹右上角轮廓，隐藏后层细节；不要增高页头，也不要挤压状态标签。
- 当前宽屏：已传 `contentMaxWidth: 1200`，图宽上限为 360，不随内容栏等比膨胀；此项源码接入已完成。
- 排版优先：状态、观看到哪一集和续播操作先于装饰。新增图片不替代收藏空态 SVG，空搜索结果继续使用搜索语义。

### P1：我的——观看票根与小册页

**语义与构图**：一册薄的观看记录纸册，一到两张没有文字与条形码的短票根，压在右侧页角。暖灰紫纸张与靛蓝票边，浅浮雕与柔和阴影。不要奖杯、等级、成就、金币和统计图；用户没有观看记录时，也不能画出“丰富收藏”的夸张堆叠。

- 已落地文件：`modern-profile-header-art.png`，2172×724 RGBA，与其他三张使用同一 3:1 比例。保留右侧票根主体与左侧文字保护区的原设计意图。
- 宿主：`profile/modern_profile_view.dart::_footprint()` 的现有装饰层，替换正常足迹卡 `modern-profile-decoration.svg` 的背景职责，不能同时叠加两张。
- 当前正常足迹卡：显示 342×114、右上锚定、opacity .20、`BoxFit.contain`，由圆角卡片裁切；没有额外左右/底部 ShaderMask。后续需重点检查 320 宽数字保护区，再决定是否缩至 220–280 或添加渐隐。
- 当前空状态：继续使用现有 80px 语义 SVG、opacity .45，与 PNG 互斥。该分支保留已落实，无需再生成一张空票根图。
- 320px：足迹卡内可用宽约 280，两个数字列已经紧凑；将纸图缩到 160–180，opacity .12–.16，或只保留右上局部。不要为插画缩小数字和说明。
- 后续宽屏建议：增加合理的统计/快捷入口编组比放大插画更重要。若实看觉得右侧过重，可把当前 342 宽缩到 280；此项是微调候选，不是当前实现值。

### P3 备用第四件：关于 / 首次引导共用的品牌片单册

在前三件实际呈现通过后再考虑。使用一本薄影院册与一张空白票根，约 3:2；可放关于品牌卡或首次引导首屏，显示 160–200px、opacity .35–.55，有独立空间才出现。帮助、隐私和每个引导步骤不各生成一张。这个候选目前不要求制作，更不应占用本轮前三件的验收时间。

## 5. 只建议二至三件局部卡片 SVG

小卡片上的“同质感”应来自圆润纸角、层叠边缘和适当的负空间，不在 SVG 里模拟纸纤维。第一件已完成素材、尚未接入；第二、三件仍是可选建议。

| 优先级 / 候选文件 | 图形构造 | 具体接入点与参数 | 必须避免 |

## 7. 三端、宽度与运行验收边界

源码确认了三端共享 Flutter 新版页面与多数图形资产；不能由共享代码推出 iPhone/iPad、Android 和 Web 已全部验证。本次文档更新已核对当前源码、四张 PNG 的存在/尺寸/通道以及搜索 SVG 引用，未重新运行浏览器或真机。接口和封面请求正在由用户修改，不在本设计任务内修复。

- **320px Web / 手机小宽度**：不增加固定页头高度；装饰应随空间减弱或隐藏。重点检查标签横滑、长标题、大字体、搜索与季度按钮命中区。图库图不裁掉主要轮廓，也不挤占文案宽度。
- **390px 手机**：检查PNG在实际渲染尺寸下仍有纸张层次，但不出现明显锯齿、白色边缘和黑底。页头、我的卡片各最多一张；列表里没有重复材质图。
- **1440px Web**：发现/日历/我的现内容宽760，追番1200，SDK900。素材跟随对应内容栏，而不是屏幕边缘；先遵守当前布局，后续再单独处理宽屏体系。图不随窗口无限放大。
- **Android**：状态栏与安全区不应被背景误染成更亮色块；低端设备滚动不因重复大图解码变卡。至少检查竖屏、横屏、系统大字体和返回。
- **iOS**：需要真机或模拟器确认安全区、侧滑返回、横屏与字体；仅凭源码不能宣称已通过。装饰不应侵入边缘返回手势，也不构成透明点击层。
- **播放器**：保留平台播放能力边界，纸张素材不修复播放来源、视频解码和跨域能力。浏览器页面能显示装饰不等于播放链路可用。

实现建议：使用真实alpha、IgnorePointer、ExcludeSemantics；保留PNG原色和接触阴影，只在宿主整体降低透明度。使用合适cacheWidth，当前影院图1080解码宽度可作为高DPR参考；不要在一屏重复解码多张原尺寸2172宽素材。最终预算应根据真实导出体积和设备测量确定，不能在未验证编码器兼容性时承诺统一转换格式。
